## 上週重點快速複習

隔了一週，先花 30 秒把進入程式實作前最關鍵的 **3 個觀念** 接回來：

<div class="grid grid-cols-3 gap-4 mt-5 text-sm">

<div class="bg-white/5 border border-sky-400/40 rounded-xl p-4">

### 1. 體 (Field) 與 $GF(p)$
- 有限集合內加減乘除皆**封閉**（不溢位、零誤差）
- 模數取**質數 $p$**，確保每個非零元素都有**乘法反元素**（可逆還原）

</div>

<div class="bg-white/5 border border-emerald-400/40 rounded-xl p-4">

### 2. $GF(2^n)$ 多項式基底
- $n$ 個 Bits 直接對應最高次方 $< n$ 的多項式
- 係數 $\in \{0,1\}$：加減法等同 **XOR ($\oplus$)**，無進位、自己就是自己的加法反元素

</div>

<div class="bg-white/5 border border-amber-400/40 rounded-xl p-4">

### 3. 乘法三步驟
1. 多項式展開
2. 係數 $\bmod 2$（偶數歸 `0`）
3. 除以 $n$ 次**不可約多項式 $m(x)$** 取餘數（把溢位次方壓回 $n$ Bits）

</div>

</div>

## 為什麼不能直接用「多項式相乘」實作？

課堂上的「多項式展開 ＋ 長除法取餘數」只是**數學概念模型**；若直接照寫成程式，會撞上嚴重的工程瓶頸：

<div class="grid grid-cols-12 gap-5 mt-3 text-sm">
<div class="col-span-7 space-y-2.5">

- **1. 時間複雜度過高**：
  - 直接雙層迴圈展開相乘＋長除法需要 **$O(n^2)$**；即使改用逐位左移累加（Shift-and-Add）仍要跑 **$O(n)$** 次迴圈與條件判斷。
  - 求**乘法反元素**（擴展歐幾里得演算法）更需多輪多項式除法，複雜度達 **$O(n^2)$**。
- **2. 海量資料放大效能瓶頸**：
  - AES 加密 1 GB 檔案或 QR Code 即時解碼，每秒需執行**數千萬至數億次** $GF(2^8)$ 乘法與反元素，迴圈＋分支會嚴重拖垮 CPU。
- **3. 分支延遲與資安風險**：
  - 每次計算依據輸入位元決定是否 XOR，執行時間不固定，易受**計時側通道攻擊 (Timing Attack)**。

</div>
<div class="col-span-5 bg-white/5 border border-white/10 rounded-xl p-3 text-xs [&_th]:!py-1.5 [&_td]:!py-1.5">

**單次運算複雜度比較**

| 運算項目 | 直接多項式計算 | 查表法 (LUT) |
|:---:|:---:|:---:|
| **加法 / 減法** | $O(1)$（XOR） | **$O(1)$（XOR）** |
| **乘法** | $O(n)$ ~ $O(n^2)$ | **$O(1)$** |
| **除法 / 反元素** | $O(n^2)$ | **$O(1)$** |
| **記憶體成本** | 極低 | **僅 512 Bytes** |

</div>
</div>

## $GF(2^3)$ 實作：先用 3-bit 小模型驗證

先用上週手算過的 **$GF(2^3)$**（模 $m(x) = x^3 + x^2 + 1 =$ `0b1101`）寫一版迷你實作，直接驗證程式與數學表完全一致：

<div class="grid grid-cols-12 gap-4 items-start mt-2">
<div class="col-span-7">

```cpp {lines:true, maxHeight:'350px'}
class GF8 {
    int exp_table[8], log_table[8];
public:
    GF8() {
        int poly = 0b1101; // x^3 + x^2 + 1
        int val = 1;
        for (int i = 0; i < 7; i++) {
            exp_table[i] = val;
            log_table[val] = i;
            val = val << 1;
            if (val >= 8) val ^= poly; // 出現 x^3 就降次
        }
        exp_table[7] = 1;
    }
    int mul(int a, int b) {
        if (a == 0 || b == 0) return 0;
        return exp_table[(log_table[a] + log_table[b]) % 7];
    }
    int inv(int a) {
        return a == 0 ? 0 : exp_table[7 - log_table[a]];
    }
};
```

</div>
<div class="col-span-5 text-xs space-y-2.5">

<div class="bg-white/5 border border-white/10 rounded-lg p-2.5 [&_th]:!py-0.5 [&_td]:!py-0.5">

**建出的完整對照表（只有 7 格！）**

| 次方 `i` | `0` | `1` | `2` | `3` | `4` | `5` | `6` |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **`exp[i]`** | 1 | 2 | 4 | 5 | 7 | 3 | 6 |

</div>

<div class="bg-emerald-500/10 border border-emerald-400/40 rounded-lg p-2.5 space-y-1">
  <div class="font-bold text-emerald-400">驗證上週手算範例：</div>
  <div>• <code>mul(7, 7)</code> = <code>exp[(4 + 4) % 7]</code> = <code>exp[1]</code> = <b>2</b> ✓</div>
  <div>• <code>inv(7)</code> = <code>exp[7 - 4]</code> = <code>exp[3]</code> = <b>5</b> ✓</div>

## 進入核心重點：為什麼真實世界用 $GF(2^8)$？

從 $GF(2^3)$ 推廣到 $GF(2^8)$，**數學規則完全沒變**，差別在於**工程上完美對應 1 Byte（8 Bits）**：

- **溢位邊界**：8 個 Bits 最高表示到 $x^7$（`11111111`）；乘法一旦出現 **$x^8$（$\ge 256$）** 就代表需要第 9 個 Bit（Overflow），必須立刻對 8 次本原多項式 `0x11D` 做 XOR 降次，壓回 1 Byte 內。

<div class="mt-3 bg-white/5 border border-white/10 rounded-lg px-4 py-2 text-sm [&_th]:!py-1.5 [&_td]:!py-1.5">

| 比較項目 | $GF(2^3)$（教學模型） | $GF(2^8)$（工程標準） |
|:---:|:---:|:---:|
| **位元寬度** | 3 Bits | **8 Bits（1 Byte）** |
| **元素總數** | $2^3 = 8$（`0`～`7`） | **$2^8 = 256$（`0`～`255`）** |
| **最高次方** | $x^2$（出現 $x^3$ 溢位） | **$x^7$（出現 $x^8$ 溢位）** |
| **本原多項式 $m(x)$** | $x^3 + x^2 + 1$（`0b1101`） | **$x^8+x^4+x^3+x^2+1$（`0x11D`）** |
| **實際用途** | 課堂手算與觀念理解 | **AES 加密、QR Code / Reed-Solomon 糾錯碼** |

</div>

### $GF(2^8)$ 完整 C++ 實作程式碼

```cpp {lines:true, maxHeight:'410px'}
#include <iostream>
using namespace std;

class GF256 {
private:
    int exp_table[256]; // 次方數 -> 係數 (數值)
    int log_table[256]; // 係數 (數值) -> 次方數

public:
    // 建構子：初始化並建立查表陣列
    GF256() {
        int poly = 0x11D; // 本原多項式 x^8 + x^4 + x^3 + x^2 + 1
        int val = 1;      // 從 g^0 = 1 開始

        // 依序產生 1~255 全部 255 個非零元素
        for (int i = 0; i < 255; i++) {
            exp_table[i] = val; // 紀錄次方數對應的係數
            log_table[val] = i; // 紀錄係數反查的次方數

            val = val << 1;     // 左移 1 位 = 乘上生成元 g = 2 (x)
            if (val >= 256) {   // 超出 8 Bits (出現 x^8) 代表溢位
                val ^= poly;    // XOR 0x11D 降次，壓回 1 Byte 內
            }
        }
        exp_table[255] = 1;     // 補上 g^255 = 1，確保 inv(1) 正確
    }

    // 加法：無進位 XOR
    int add(int a, int b) {
        return a ^ b;
    }

    // 減法：係數 mod 2 下與加法相同
    int sub(int a, int b) {
        return a ^ b;
    }

    // 乘法：次方數相加 (mod 255) 再查回係數
    int mul(int a, int b) {
        if (a == 0 || b == 0) return 0; // 0 沒有對應的次方數
        return exp_table[(log_table[a] + log_table[b]) % 255];
    }

    // 除法：次方數相減 (加 255 避免負數) 再查回係數
    int div(int a, int b) {
        if (a == 0 || b == 0) return 0; // 避免 0 或除以 0
        return exp_table[(log_table[a] - log_table[b] + 255) % 255];
    }

    // 乘法反元素：用 255 減掉次方數再查回係數
    int inv(int a) {
        if (a == 0) return 0; // 0 沒有乘法反元素
        return exp_table[255 - log_table[a]];
    }
};
```

### $GF(2^8)$ 核心位元運算解析：`val << 1` 與溢位降次

這三行程式碼就是把「**多項式乘上 $x$**」與「**除以 $m(x)$ 取餘數**」直接用 CPU 位元運算完成：

```cpp
val = val << 1;          // 1. 左移 1 位 = 多項式乘上 x (2)
if (val >= 256) {        // 2. 檢查是否超出 8 Bits (出現 x^8)
    val ^= poly;         // 3. XOR 0x11D 消去 x^8，壓回 1 Byte
}
```

<div class="grid grid-cols-2 gap-4 mt-3 text-xs">

<div class="bg-white/5 border border-emerald-400/40 rounded-lg p-3">

**情況 A：未溢位（例：`val = 4`）**
- 原本：`0000 0100`（$x^2$）
- 左移 `<< 1`：`0000 1000`（$x^3 = 8$）
- 結果 `8 < 256`，沒有超出 8 Bits，直接結束！

</div>

<div class="bg-amber-500/15 border border-amber-400/40 rounded-lg p-3">

**情況 B：觸發溢位（例：`val = 128`）**
- 原本：`1000 0000`（$x^7 = 128$）
- 左移 `<< 1`：**`1 0000 0000`**（$x^8 = 256 \ge 256$，溢位！）
- 立刻 XOR `0x11D`（`1 0001 1101`）：

```text
  1 0000 0000  (256 = x^8)
^ 1 0001 1101  (0x11D = x^8+x^4+x^3+x^2+1)
─────────────
  0 0001 1101  (29  = x^4+x^3+x^2+1)
```

</div>

## 查表規則總整理（$GF(2^8)$ 速查表）

只要掌握這兩張表的對應關係（**`exp_table[次方數] = 係數`**、**`log_table[係數] = 次方數`**），所有運算都能套用固定規則在 $O(1)$ 完成：

<div class="mt-3 bg-white/5 border border-white/10 rounded-xl px-4 py-2 text-sm [&_th]:!py-1.5 [&_td]:!py-1.5">

| 運算項目 | 查表公式（$GF(2^8)$，週期 $= 255$） | 關鍵防呆與規則 |
|:---:|:---|:---|
| **加法 / 減法** | `a ^ b` | 不需查表，直接位元 XOR |
| **乘法 `mul(a, b)`** | `exp[(log[a] + log[b]) % 255]` | 若 `a == 0` 或 `b == 0`，直接回傳 `0` |
| **除法 `div(a, b)`** | `exp[(log[a] - log[b] + 255) % 255]` | 減法先 **`+ 255`** 防止負索引；不可除以 `0` |
| **反元素 `inv(a)`** | `exp[255 - log[a]]` | 須補 **`exp[255] = 1`**（否則 `inv(1)` 讀錯）；`0` 無反元素 |

</div>

<div class="mt-3 text-xs opacity-85 text-center">
💡 <b>記憶口訣</b>：非零先防呆 → 用 <code>log_table</code> 換成<b>次方數</b> → 次方做加減（對 255 循環）→ 用 <code>exp_table</code> 換回<b>係數</b>！
</div>

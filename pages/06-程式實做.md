## 程式實作：$GF(2^8)$ 查表法原理

在密碼學實務中，每次乘法都做「多項式展開＋長除法」會拖垮 CPU；改用**查表法 (Look-up Table)**，以空間換時間，將乘法降為 **$O(1)$**。

<div class="grid grid-cols-2 gap-5 mt-4 text-sm">
<div class="bg-white/5 border border-white/10 rounded-xl p-4">

### 核心概念：對數律
$$g^a \times g^b = g^{(a + b) \bmod 255}$$
- **`exp_table[i]`**：記錄生成元 $g^i$ 的值
- **`log_table[x]`**：反查 $x$ 對應的指數 $i$
- 把複雜的**乘法**降階成單純的**查表＋加法**

</div>
<div class="bg-white/5 border border-white/10 rounded-xl p-4">

### 運算流程對照
1. 輸入兩個 Byte：$a, b$
2. 查對數表：$i = \text{log}[a]$、$j = \text{log}[b]$
3. 指數相加：$k = (i + j) \bmod 255$
4. 查指數表：回傳 $\text{exp}[k]$

</div>
</div>

### 1. 建表實作：生成 `exp_table` 與 `log_table`

<div class="grid grid-cols-12 gap-5 items-start mt-3">
<div class="col-span-7">

```cpp {lines:true}
const int poly = 0x11B; // x^8+x^4+x^3+x+1
int exp_table[256], log_table[256];

int x = 1;
for (int i = 0; i < 255; ++i) {
    exp_table[i] = x;
    log_table[x] = i;

    // 乘生成元 g = 3 (x+1)：(x*2) XOR x
    int x2 = x << 1;
    if (x2 & 256) x2 ^= poly; // 溢位降次
    x = x2 ^ x;
}
exp_table[255] = 1; // 補齊 inverse(1)
```

### 2. $O(1)$ 四則與反元素實作

<div class="grid grid-cols-12 gap-5 items-start mt-3">
<div class="col-span-7">

```cpp {lines:true}
// 加減法：直接 XOR（無進位）
int add(int a, int b) {
    return a ^ b;
}

// 乘法：查 log 相加 → 查 exp
int multiply(int a, int b) {
    if (a == 0 || b == 0) return 0;
    return exp_table[(log_table[a] + log_table[b]) % 255];
}

// 乘法反元素（AES S-Box 核心）
int inverse(int a) {
    if (a == 0) return 0;
    return exp_table[255 - log_table[a]];
}
```

### 進入真實世界：為什麼是 $GF(2^8)$ ？

前面我們利用 $GF(2^3)$ 徹底理解了多項式的 XOR 抵銷與降次代換。但回到真實的計算機科學領域，我們最需要也最常使用的，是 **$GF(2^8)$**。

#### 1. 什麼時候會發生溢位 (Overflow)？
在 $GF(2^8)$ 的空間中，一個元素剛好對應電腦底層的 **1 Byte (8 Bits)**。
這 8 個 Bits 能表示的最高次方是 **$x^7$**（例如二進位 `11111111` $= x^7+x^6+...+1$）。

* **觸發溢位的瞬間**：當我們進行乘法運算時，只要產生了 **$x^8$ 或更高的次方**，就代表需要「第 9 個 Bit」才能儲存，這在 8-bit 的資料結構中就會發生 Overflow。
* **解決方案**：一旦偵測到 $x^8$ 出現，系統就會立刻除以 8 次的不可約多項式 $m(x)$ ，透過 XOR 取餘數，將超出邊界的次方完美壓回 1 Byte 的空間內，保證資料永遠不會因溢位而遺失或失真。

---
---
#### 2. 從 $GF(2^3)$ 到 $GF(2^8)$ 的根本差異
推廣到 8 次方後，數學運算規則（加減法等於 XOR、找質式降次）完全沒有改變，真正的差異在於**工程上的意義**：
* **$GF(2^3)$**：空間太小（只有 8 種變化），只能作為數學課堂上的概念模型。
* **$GF(2^8)$**：空間剛好是 256 種變化，完美對應 ASCII 碼、像素顏色 (0~255)、以及記憶體中的任何一個 Byte。**我們把電腦裡所有的 Byte，都變成了可以做嚴格代數運算的數學實體。**

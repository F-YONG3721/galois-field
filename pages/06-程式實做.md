## 程式實作：GF( $2^8$ ) 

在密碼學實務中，我們需要對海量的位元組進行加密。如果每一次乘法都要跑迴圈慢慢做「多項式展開」與「除法取餘數」，會嚴重拖垮 CPU 的效能。

因此，在資工實作上，我們會採用「查表法 (Look-up Table)」，利用空間換取時間，將複雜的代數運算降階為 $O(1)$ 的陣列讀取。

### 1. 核心演算法架構：指數表與對數表
利用對數律 $x^a \times x^b = x^{a+b}$ 的特性，我們可以將「乘法」降階為「對數的加法」。
在建構子 (Constructor) 初始化時，我們先預先算好 256 個元素的變化，建立兩張表：
* **`exp_table` (指數表)**：記錄 $g^i$ 的值（遇到溢位就 XOR 不可約多項式 `0x11B` 降次）。
* **`log_table` (對數表)**：記錄反向對應的指數，用來將數字轉為對數相加。

### 2. C++ 核心實作程式碼
```cpp {lines:true, maxHeight:'410px'} 

class GaloisField {
    int exp_table[256], log_table[256];

public:
    GaloisField() {
        const int poly = 0x11B; // AES 不可約多項式 x^8+x^4+x^3+x+1
        int x = 1;
        for (int i = 0; i < 255; ++i) {
            exp_table[i] = x;
            log_table[x] = i;   // 補上對數表對應

            // 乘上生成元 g = 3 (x + 1)：等於 (x * 2) XOR x
            int x2 = x << 1;
            if (x2 & 256) x2 ^= poly;
            x = x2 ^ x;
        }
        exp_table[255] = 1;     // 修正 inverse(1) 邊界條件
    }

    int add(int a, int b) { return a ^ b; } // 加減法皆為 XOR

    int multiply(int a, int b) {
        if (a == 0 || b == 0) return 0;
        return exp_table[(log_table[a] + log_table[b]) % 255];
    }

    int inverse(int a) {
        if (a == 0) return 0; // 0 無乘法反元素
        return exp_table[255 - log_table[a]];
    }
};

```

### 進入真實世界：為什麼是 $GF(2^8)$ ？

前面我們利用 $GF(2^3)$ 徹底理解了多項式的 XOR 抵銷與降次代換。但回到真實的計算機科學領域，我們最需要也最常使用的，是 **$GF(2^8)$**。

#### 1. 什麼時候會發生溢位 (Overflow)？
在 $GF(2^8)$ 的空間中，一個元素剛好對應電腦底層的 **1 Byte (8 Bits)**。
這 8 個 Bits 能表示的最高次方是 **$x^7$**（例如二進位 `11111111` $= x^7+x^6+...+1$）。

* **觸發溢位的瞬間**：當我們進行乘法運算時，只要產生了 **$x^8$ 或更高的次方**，就代表需要「第 9 個 Bit」才能儲存，這在 8-bit 的資料結構中就會發生 Overflow。
* **解決方案**：一旦偵測到 $x^8$ 出現，系統就會立刻除以 8 次的不可約多項式 $m(x)$ ，透過 XOR 取餘數，將超出邊界的次方完美壓回 1 Byte 的空間內，保證資料永遠不會因溢位而遺失或失真。

---
---
#### 2. 從 $GF(2^3)$ 到 $GF(2^8)$ 的根本差異
推廣到 8 次方後，數學運算規則（加減法等於 XOR、找質式降次）完全沒有改變，真正的差異在於**工程上的意義**：
* **$GF(2^3)$**：空間太小（只有 8 種變化），只能作為數學課堂上的概念模型。
* **$GF(2^8)$**：空間剛好是 256 種變化，完美對應 ASCII 碼、像素顏色 (0~255)、以及記憶體中的任何一個 Byte。**我們把電腦裡所有的 Byte，都變成了可以做嚴格代數運算的數學實體。**

### 1. 什麼是體 (Field)？
- 一個有限集合，同時定義**加法**與**乘法**
- 運算結果永遠留在集合內（**封閉性**）
- 每個非零元素皆存在唯一**乘法反元素**（可做除法、可 100% 還原）

</div>

<div class="bg-white/5 border border-emerald-400/40 rounded-xl p-4">

### 2. 常數與多項式
- **常數 $GF(p)$**：整數 $\bmod$ 質數 $p$（如 $GF(7)$）
- **多項式 $GF(2^n)$**：$n$ 個 Bits 直接對應 $n-1$ 次多項式，係數只能是 `0` 或 `1`
- 係數 $\bmod 2$：加減法完全等同 **XOR ($\oplus$)**

</div>

<div class="bg-white/5 border border-amber-400/40 rounded-xl p-4">

### 3. 如果 Overflow 怎麼辦？
- 乘法產生最高次方 $\ge n$（超出 $n$ Bits 邊界）時發生 **Overflow**
- 解法：除以預先選定的 $n$ 次**不可約多項式 $m(x)$** 取餘數
- 餘式次方必定 $< n$，完美壓回固定位寬內

</div>

</div>

## 為什麼不能直接用「多項式相乘」實作？

紙上的「多項式展開 ＋ 長除法取餘數」只是數學概念；在程式實作上，最致命的瓶頸是 **時間複雜度**：

<div class="grid grid-cols-12 gap-5 mt-3 text-sm">
<div class="col-span-7 space-y-3">

- **1. 直接展開＋長除法：$O(n^2)$**
  - 兩個 $n-1$ 次多項式逐項相乘，需要 $n \times n$ 次運算（雙層迴圈）。
  - 乘完次方衝到 $2n-2$，還要再跑多項式長除法一路降回 $< n$，又是 **$O(n^2)$**。
- **2. 改用二進位 Shift + XOR：仍需 $O(n)$**
  - 即使改成逐位左移＋條件 XOR，每一次乘法仍必須跑完 $n$ 輪迴圈（$GF(2^8)$ 每次乘要跑 8 輪）。
  - 若要求**乘法反元素**（擴展歐幾里得演算法），仍需要多輪多項式除法，複雜度達 **$O(n^2)$**。
- **3. 實務上的放大效應**：
  - 加解密一個大型檔案每秒需做**上億次** $GF(2^8)$ 乘法與反元素；把每次運算從 $O(n) / O(n^2)$ 降到 **$O(1)$ 查表**，效能差距極大。

</div>
<div class="col-span-5 bg-white/5 border border-white/10 rounded-xl p-3.5 text-xs [&_th]:!py-2 [&_td]:!py-2">

**單次運算時間複雜度對照**

| 運算項目 | 直接展開／長除 | Shift + XOR | 查表法 (LUT) |
|:---:|:---:|:---:|:---:|
| **加／減法** | $O(n)$ | $O(1)$ | **$O(1)$** |
| **乘法** | $O(n^2)$ | $O(n)$ | **$O(1)$** |
| **反元素／除法** | $O(n^2)$ | $O(n^2)$ | **$O(1)$** |

</div>

## $GF(2^8)$ 二進位乘法：Shift + XOR 計算方式

不靠查表時，電腦會把「乘上 $x$（`00000010`）」化簡為 **左移 1 位 ＋ 判斷最高位 $b_7$ 是否溢位**：

$$x \times f(x) = \begin{cases} (b_6 b_5 b_4 b_3 b_2 b_1 b_0 0) & \text{if } b_7 = 0 \\ (b_6 b_5 b_4 b_3 b_2 b_1 b_0 0) \oplus (00011011) & \text{if } b_7 = 1 \end{cases}$$

## 進入 $GF(2^8)$ 程式實作：為什麼是 $GF(2^8)$？

推廣到 $GF(2^8)$ 後，運算規則與 $GF(2^3)$ 完全相同，差別在於工程上剛好對應 **1 Byte（8 Bits）**：

<div class="mt-4 bg-white/5 border border-white/10 rounded-lg px-4 py-2 text-sm [&_th]:!py-1.5 [&_td]:!py-1.5">

| 比較項目 | $GF(2^3)$（概念模型） | $GF(2^8)$（工程標準） |
|:---:|:---:|:---:|
| **位元寬度** | 3 Bits | **8 Bits（1 Byte）** |
| **元素總數** | $2^3 = 8$（`0`～`7`） | **$2^8 = 256$（`0`～`255`）** |
| **最高次方與溢位** | 最高 $x^2$（$x^3$ 溢位） | **最高 $x^7$（$x^8$ 溢位）** |
| **本原多項式 $m(x)$** | $x^3 + x^2 + 1$（`0b1101`） | **$x^8+x^4+x^3+x^2+1$（`0x11D`）** |
| **實際用途** | 課堂手算推導 | **AES 加密、QR Code / Reed-Solomon 糾錯碼** |

</div>

## 查表法詳細說明：`exp_table` 與 `log_table`

為了把乘法與反元素從 $O(n) / O(n^2)$ 壓到 **$O(1)$**，我們預先建立兩張 256 格的對照表：

<div class="grid grid-cols-12 gap-4 mt-2 text-xs">
<div class="col-span-6 space-y-2">

<div class="bg-white/5 border border-sky-400/40 rounded-lg p-3">

**1. 建表原理：生成元 $g = 2$（模 `0x11D`）**
- 從 `val = 1`（$g^0$）開始，每輪左移 1 位（`<< 1`），若 `>= 256` 就 XOR `0x11D` 降次。
- 跑 255 輪後，剛好**不重複走完 `1`～`255` 全部非零元素**，第 255 步繞回 `1`（$g^{255} = 1$）。

</div>

<div class="bg-white/5 border border-emerald-400/40 rounded-lg p-3">

**2. 兩張表互相對照（次方數 $\leftrightarrow$ 係數）**
- **`exp_table[次方數] = 係數`**：查第 $i$ 次方對應哪個 Byte（例：`exp[0]=1, exp[1]=2, exp[8]=29`）
- **`log_table[係數] = 次方數`**：反查某個 Byte 是第幾次方（例：`log[1]=0, log[2]=1, log[29]=8`）

</div>

</div>
<div class="col-span-6 bg-white/5 border border-white/10 rounded-lg p-3 [&_th]:!py-1 [&_td]:!py-1">

**3. 所有運算的查表規則（$O(1)$ 速查）**

| 運算 | 查表公式 | 注意事項 |
|:---:|:---|:---|
| **加／減** | `a ^ b` | 直接 XOR，不需查表 |
| **乘法** | `exp[(log[a] + log[b]) % 255]` | `a` 或 `b` 為 `0` 直接回傳 `0` |
| **除法** | `exp[(log[a] - log[b] + 255) % 255]` | 先 `+ 255` 防負索引；不可除以 `0` |
| **反元素** | `exp[255 - log[a]]` | 需補 **`exp[255] = 1`**（否則 `inv(1)` 讀錯） |

<div class="mt-2 pt-2 border-t border-white/15 opacity-90">
💡 <b>記憶口訣</b>：非零防呆 → 查 <code>log</code> 換<b>次方數</b> → 次方加減（模 255）→ 查 <code>exp</code> 換回<b>係數</b>！
</div>

</div>
</div>

### $GF(2^8)$ 完整 C++ 實作程式碼

```cpp {lines:true, maxHeight:'410px'}
#include <iostream>
using namespace std;

class GF256 {
private:
    int exp_table[256]; // 次方數 -> 係數 (數值)
    int log_table[256]; // 係數 (數值) -> 次方數

public:
    // 建構子：初始化並建立查表陣列
    GF256() {
        int poly = 0x11D; // 本原多項式 x^8 + x^4 + x^3 + x^2 + 1
        int val = 1;      // 從 g^0 = 1 開始

        // 依序產生 1~255 全部 255 個非零元素
        for (int i = 0; i < 255; i++) {
            exp_table[i] = val; // 紀錄次方數對應的係數
            log_table[val] = i; // 紀錄係數反查的次方數

            val = val << 1;     // 左移 1 位 = 乘上生成元 g = 2 (x)
            if (val >= 256) {   // 超出 8 Bits (出現 x^8) 代表溢位
                val ^= poly;    // XOR 0x11D 降次，壓回 1 Byte 內
            }
        }
        exp_table[255] = 1;     // 補上 g^255 = 1，確保 inv(1) 正確
    }

    // 加法：無進位 XOR
    int add(int a, int b) {
        return a ^ b;
    }

    // 減法：係數 mod 2 下與加法相同
    int sub(int a, int b) {
        return a ^ b;
    }

    // 乘法：次方數相加 (mod 255) 再查回係數
    int mul(int a, int b) {
        if (a == 0 || b == 0) return 0; // 0 沒有對應的次方數
        return exp_table[(log_table[a] + log_table[b]) % 255];
    }

    // 除法：次方數相減 (加 255 避免負數) 再查回係數
    int div(int a, int b) {
        if (a == 0 || b == 0) return 0; // 避免 0 或除以 0
        return exp_table[(log_table[a] - log_table[b] + 255) % 255];
    }

    // 乘法反元素：用 255 減掉次方數再查回係數
    int inv(int a) {
        if (a == 0) return 0; // 0 沒有乘法反元素
        return exp_table[255 - log_table[a]];
    }
};
```
